## BUG-001 — Quantity = 0 замінюється на 1 замість повідомлення про помилку
**Severity:** Minor  **Priority:** P3  **Linked:** TC-014; GUI-30 (SRS 1.1)
**Description:** SRS 1.1 допускає кількість 1–99; значення 0 має відхилятися повідомленням про допустимий діапазон. Demo підставляє 1 без повідомлення і після «Add to cart» додає товар у кількості 1, тому покупець не дізнається про помилку введення. Severity Minor: помилка некритична, кількість лишається допустимою, її можна змінити в кошику. P3: інші кейси не блокує.
**Steps to reproduce:**
1. Відкрити https://practicesoftwaretesting.com у Chromium 157.0.8103.39 (нова сесія, інкогніто).
2. Натиснути картку «Combination Pliers».
3. У полі «Quantity» видалити значення і ввести 0.
4. Клікнути поза полем «Quantity» (вийти з поля).
5. Натиснути «Add to cart».
**Actual result:** 0 змінюється на 1 (точний момент автозаміни у незалежному повторі відрізнявся; на знімку є «Product quantity updated»); повідомлення про допустимий діапазон немає. Після кроку 5 товар додано в кошик у кількості 1: у кошику рядок «Combination Pliers», Quantity = 1; лічильник кошика = 1.
**Expected result:** Після кроку 4 або 5 біля поля повідомлення про допустимий діапазон 1–99; товар не додано; лічильник кошика не змінився (GUI-30).
**Environment:** demo 15.11.2026 (збірка v2.5, Built 2026-10-11 — за підвалом сторінки); Chromium 157.0.8103.39; Windows 11; без входу.
**Attachments:** attachments/BUG-001-1.jpg — кошик: «Combination Pliers», Quantity = 1, лічильник = 1; повідомлення «Product quantity updated».

**Reviewer:** Петренко Валентин · 16.11.2026 · Зауваження первинної рецензії враховані у редакції автора; повторне погодження не підтверджено.

## BUG-002 — Кошик допускає кількість понад 99 після повторного додавання
**Severity:** Major  **Priority:** P3  **Linked:** TC-017; F-90 (пов’язано BL-20)
**Description:** F-90 вимагає, щоб повторне додавання збільшувало кількість у кошику; обмеження 99 на рядок задає BL-20 (SRS 1.1). Demo не відхиляє повторне додавання понад 99. На знімку автора зафіксовано Quantity = 101; вихідний стан цього знімка не доводить сценарій 50 + 50. Незалежний аудитор підтвердив 50 + 50 → 100 з порожнього кошика. Перевіряється лише поведінка UI: виняток методу `Cart.addItem` цим звітом не перевірявся. Severity Major: контроль ліміту не працює, але замовлення з допустимою кількістю оформити можна. P3: кейси не блокує.
**Steps to reproduce:**
1. Відкрити https://practicesoftwaretesting.com у Chromium 157.0.8103.39 (нова сесія, інкогніто, кошик порожній).
2. Натиснути картку «Combination Pliers».
3. У полі «Quantity» ввести 50, натиснути «Add to cart».
4. Натиснути піктограму кошика.
5. Повернутися на сторінку товару, у полі «Quantity» ввести 50, натиснути «Add to cart».
6. Натиснути піктограму кошика.
**Actual result:** За незалежним повтором аудитора після першого додавання у кошику один рядок «Combination Pliers», Quantity = 50. Після повторного додавання перевищення 99 не відхилено. На attachments/BUG-002-1.jpg видно Quantity = 101 і Total = $1,429.15. Скріншот автора показує Quantity = 101 і Total = $1,429.15; незалежне відтворення аудитора для 50 + 50 дало Quantity = 100. Обидва результати перевищують 99; точні умови знімка автора не встановлено.
**Expected result:** Після кроку 5 — повідомлення про перевищення 99; лічильник лишається 50; після кроку 6 в одному рядку Quantity = 50.
**Environment:** demo 15.11.2026 (збірка v2.5, Built 2026-10-11 — за підвалом сторінки); Chromium 157.0.8103.39; Windows 11; без входу.
**Attachments:** attachments/BUG-002-1.jpg — кошик із Quantity = 101 і Total = $1,429.15. Незалежне підтвердження 50 + 50 → 100 описано у `audit.md`; знімок автора не є його доказом.

**Expected result:** У підсумку на кроці «Payment» є рядок «Shipping» з вартістю доставки (F-110).
**Environment:** demo 15.11.2026 (збірка v2.5, Built 2026-10-11 — за підвалом сторінки); Chromium 157.0.8103.39; Windows 11; customer@practicesoftwaretesting.com.
