## BUG-001 — Quantity = 0 замінюється на 1 без помилки

| Поле | Значення |
|:---|:---|
| Bug ID | BUG-001 |
| Severity | Minor |

| Status | New |
| Reporter | Черватюк Євгеній |
| Linked test / session | TC-014 |
| Linked requirement | GUI-30 (SRS 1.1) |

### Опис

У полі Quantity введене 0 автоматично замінюється на 1 без повідомлення про допустимий діапазон. За повтором аудитора точний момент автозаміни відрізнявся.

0 замінюється на 1 без повідомлення про діапазон; після додавання у кошику Combination Pliers, Quantity = 1, лічильник = 1. На скриншоті видно «Product quantity updated».

### Середовище

Chromium 157.0.8103.39; Windows 11; гість; 15.11.2026; v2.5 (за footer demo).

### Скріншот

**BUG-001.jpg** — Кошик із Combination Pliers, Quantity = 1; показано результат автозаміни введеного 0.

## BUG-002 — Повторне додавання перевищує ліміт 99

| Поле | Значення |
|:---|:---|
| Bug ID | BUG-002 |
| Severity | Major |
| Priority | P3 |
| Status | New |
| Reporter | Черватюк Євгеній |
| Linked test / session | TC-017 |
| Linked requirement | F-90; BL-20 (контекст) (SRS 1.1) |

### Опис

В UI за повторного додавання того самого товару сумарна кількість може перевищувати 99. Незалежний аудитор відтворив 50 + 50 → 100; на знімку автора інший випадок Quantity = 101. Це не тест винятку Java-методу Cart.

### Передумови

Доступ до demo; для сценаріїв кошика — нова сесія з порожнім кошиком. Додаткові умови уточнено в кроках.

### Кроки відтворення

1. Почати нову гостьову сесію з порожнім кошиком.
2. Відкрити Combination Pliers, встановити Quantity = 50 та натиснути Add to cart.
3. Відкрити кошик і зафіксувати Quantity = 50.
4. Повернутися до Combination Pliers, знову встановити 50, натиснути Add to cart.
5. Перейти до кошика та перевірити кількість.

### Фактичний результат

За незалежним аудитом друга операція не відхилена, у кошику Quantity = 100. Окремий скриншот автора показує 101 і $1,429.15; послідовність кроків, що привела до 101, не відтворена.

### Очікуваний результат

Повідомлення про перевищення 99; друга операція відхилена, рядок залишається з Quantity = 50 (F-90).

### Середовище

Chromium 157.0.8103.39; Windows 11; гість; 15.11.2026; v2.5 (за footer demo).

### Скріншот

**BUG-002.jpg** — Кошик із Quantity = 101 — перевищено ліміт 99.

### Рецензування та стан зауважень

**Reviewer:** Петренко Валентин · 17.11.2026 · Погоджено. Сценарій 50 + 50 → 100 зафіксовано в незалежному аудиті. Межу 99 і очікувану відмову наведено за F-90.

## BUG-007 — Кнопки + і − не змінюють Quantity

### Опис

Під час дослідницького тестування користувач повідомив про відсутність реакції кнопок зміни кількості. Для кнопки «−» важливо перевіряти кількість вище 1 — натискання «−» на мінімальному значенні 1 не є помилкою.

4. Якщо кнопка «+» не працює, вручну ввести допустиме Quantity = 3; натиснути «−».

За послідовністю 1 → 2 → 3 → 2 кількість змінюється; за початкового 1 кнопка «−» не повинна зменшувати нижче межі (F-80, GUI-30).

### Середовище

Настільний браузер; версія й ОС під час цього прогону не зафіксовані; гість; 16.11.2026.

### Скріншот

### Опис

За повідомленням виконавця, натискання хрестика у Cart не видаляє Combination Pliers. Скріншот лише показує кнопку і поточний рядок — сам клік на ньому не видно.

### Передумови

Доступ до demo; для сценаріїв кошика — нова сесія з порожнім кошиком. Додаткові умови уточнено в кроках.

### Кроки відтворення

1. Почати з порожнім кошиком, додати один Combination Pliers.
2. Відкрити Cart, зафіксувати стан перед натисканням «×».
3. Натиснути «×», перевірити стан одразу після кліку.
4. Оновити сторінку й знову перевірити стан кошика.

### Фактичний результат

За повторним ручним прогоном виконавця товар залишається в кошику після натискання «×». Результат після оновлення сторінки окремо письмово не уточнювався.

### Очікуваний результат

Рядок Combination Pliers зникає; порожній кошик показує текстове повідомлення замість таблиці (F-100, GUI-70).

### Середовище

Настільний браузер; версія й ОС не зафіксовані; гість; 16.11.2026.

### Скріншот

## BUG-010 — Home на Contact не повертає до каталогу

| Поле | Значення |
|:---|:---|
| Bug ID | BUG-010 |
| Severity | Normal |
| Priority | P3 |
| Status | New |
| Reporter | Черватюк Євгеній |
| Linked test / session | Додаткова перевірка (дослідницька) |
| Linked requirement | GUI-10 (SRS 1.1) |

### Опис

За двома ручними повтореннями виконавця натискання Home на Contact залишає / відкриває сторінку Contact, замість головного каталогу. Адресу після натискання не зафіксовано.

### Передумови

Доступ до demo; для сценаріїв кошика — нова сесія з порожнім кошиком. Додаткові умови уточнено в кроках.

### Кроки відтворення

1. Відкрити https://practicesoftwaretesting.com/contact.
2. Зробити кадр/запис URL та сторінки Contact до натискання.
3. Натиснути Home у шапці сторінки.
4. Зафіксувати URL і вміст після натискання.
5. Повторити сценарій для перевірки відтворюваності.

### Фактичний результат

Виконавець повідомив про дворазове відкриття Contact замість каталогу. Доступний скриншот показує Contact з пунктом Home, але не доводить URL і перехід після кліку.

### Очікуваний результат

Після Home має відкриватися головна сторінка каталогу (GUI-10).

### Середовище

Настільний браузер; версія, ОС та ширина вікна не зафіксовані; гість; 16.11.2026.

### Скріншот

**BUG-010.png** — Сторінка Contact з пунктом Home; самого переходу після натискання на кадрі не видно.

### Рецензування та стан зауважень

**Reviewer:** Петренко Валентин · 17.11.2026 · Погоджено. У Run 2, EXP-004, зафіксовано, що після Home двічі відкрилася сторінка Contact. Цього достатньо для описаного прояву навігації за GUI-10.
