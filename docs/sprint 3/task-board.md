### Як закрити рецензію

1. Відкрити аркуші рецензування у [task-board.xlsx](task-board.xlsx). Для кейсу звірити всі 8 пунктів §5.3. Для звіту звірити 7 правил і обов’язкові поля, зокрема середовище, прив’язку до вимоги, severity/priority і докази.
2. Передати конкретне зауваження ТА або ІТ. Автор оновлює артефакт. СМ звіряє правку.
3. У тест-кейсах зафіксувати рецензента, дату й результат в аркуші Review і позначити reviewed після виконання критеріїв. У звітах заповнити Reviewer і дату. Зауваження з цієї книги — робочий матеріал для фактичної рецензії.

## Посилання для GitHub і робочої групи

- **Перегляд із GitHub.** Закомітити цей Markdown і `task-board.xlsx` в одну папку `docs/sprint3/`. Посилання на початку вже відносне. Воно відкриває зафіксовану версію XLSX для тих, хто має доступ до репозиторію. У публічному репозиторії її зможе відкрити будь-хто.
- **Редагування командою.** Імпортувати XLSX в Google Sheets, видати доступ Editor на Google-акаунти учасників і надіслати URL робочої таблиці в командний чат. Робочу таблицю можна залишити Restricted. Після оновлень експортувати новий XLSX і замінити файл у GitHub.
- **Якщо потрібен живий перегляд із GitHub.** Замість посилання на XLSX вставити посилання на Google Sheets із загальним доступом «Anyone with the link → Viewer». Учасникам залишити окремо виданий Editor на їхні акаунти. Перевірити права за посиланням у приватному вікні та з акаунта редактора. Різницю в правах визначають налаштування доступу й акаунти.
